- **핵심 내용 (본인 요약, 의역 — 직접 인용 아님):**
  - `initialize` 핸드셰이크와 세션 기반 라우팅을 제거하고 상태 비저장(stateless) 코어로 전환. 서버가 sticky session이나 공유 세션 스토어 없이 일반 라운드로빈 로드밸런서 뒤에서 동작 가능해짐.
  - Extensions 프레임워크 공식화(역-DNS 식별자, 독립 버저닝).
  - MCP Apps: 서버가 샌드박스 iframe에 인터랙티브 HTML UI를 제공 가능.
  - Tasks가 실험적 코어 기능에서 별도 extension으로 격하/재설계(기존 구현은 마이그레이션 필요).
  - Roots·Sampling·Logging은 12개월 제거 유예를 두고 deprecated.
  - Tool schema가 JSON Schema 2020-12 전체 지원(조건부·조합·참조 가능).
- **Jayden 적용 가능성:** n8n/Claude API 조합에서 MCP 서버를 쓰고 있다면 세션리스 전환은 인프라 단순화(로드밸런서만으로 스케일)로 이어짐. 단, Tasks/Roots를 쓰는 커스텀 MCP 서버가 있다면 마이그레이션 필요 — 지금 당장 액션 아님, RC 단계라 최종 확정(7/28) 후 재확인 권장.

### 🔵 필시청 — Anthropic Workshop: Build Agents That Run for Hours
- **채널:** AI Engineer (구독자 542K, 공식 컨퍼런스 채널) · **발표자:** Ash Prabaker, Andrew Wilson

- **링크:** https://www.youtube.com/watch?v=mR-WAvEPRwE
- **자막:** yt-dlp로 네이티브 자막 확보 성공 (전체 시청 텍스트 기반 요약, 프레임 미분석)
- **댓글 검증:** 미실시(시간 예산 내 자막 확보를 우선함 — 메타에 누락 명시)

**핵심 주장 (한 줄):** 에이전트가 자기 작업을 스스로 평가(self-evaluation)하는 방식은 함정이며, 별도 컨텍스트·시스템 프롬프트를 가진 "adversarial evaluator"에게 실제 도구(Playwright 등)로 라이브 검증을 시켜야 한다.

**시연된 워크플로우 (자막 확인, 5단계):**
1. Generator(빌더) 에이전트가 독립된 컨텍스트에서 코드를 작성.
2. Evaluator 에이전트는 diff만 읽지 않고 Playwright로 실제 페이지를 열어 클릭·조작하며 검증 (별도 시스템 프롬프트로 "harsh"하게 튜닝).
3. Evaluator가 critique를 generator에게 돌려주고 루프 반복 (GAN의 generator/discriminator 구조를 명시적으로 차용했다고 발표자가 언급).
4. 컨텍스트 리셋 시 손실 요약(lossy compaction)에 의존하지 말고 구조화된 handoff 문서로 상태를 전달.
5. 주관적 품질(코드 스타일, UX 등)도 "이렇게 보여야 한다"는 기준을 명시적 rubric으로 문서화해 evaluator가 채점 가능하게 만듦.

**사용된 도구·repo (자막/설명란 확인):** Claude Agent SDK, Claude Code, Playwright MCP, Claude for Chrome MCP, computer use, Claude Code skills(rubric 패키징 용도), "auto mode"(`--dangerously-skip-permissions`보다 안전한 대안으로 언급).

**발표자 마무리 5행 요약 (자막 발췌, 의역):** self-evaluation은 함정 → adversarial evaluator 사용 / compaction ≠ coherence, 손실 요약은 drift를 유발 → 구조화된 handoff와 clean context 사용 / 주관적 품질도 rubric으로 명문화 가능 / 트레이스를 직접 읽는 것이 최선의 디버깅 루프 → 이걸 기준으로 harness의 어떤 부분을 남기고 버릴지 판단.

**Jayden 스택 적용 가능성:** Next.js+Supabase 프로젝트에서 PR/기능 검증을 "같은 Claude Code 세션이 자기 코드 리뷰"하는 대신, 별도 서브에이전트를 evaluator 역할로 분리하고 Playwright MCP로 스테이징 환경을 직접 조작해 검증하게 하는 패턴을 n8n QA 단계에 이식 가능. PayLoom·PG-System처럼 자동화 금지 영역은 이 패턴 적용 대상에서 제외 대상임에 유의.
