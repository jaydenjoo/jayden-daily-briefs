주요 변경:
- **Stateless core**: `initialize` handshake 및 `Mcp-Session-Id` 제거 → 일반 round-robin 로드 밸런서에서 배포 가능. 클라이언트 메타는 요청별 `_meta` 필드로 이동.

- **Tasks extension**: 장기 실행 작업을 stateless request/response로 처리 (experimental에서 공식화).
- **Authorization**: OAuth 2.0 / OpenID Connect 정렬 강화, RFC 9207 issuer 검증.
- **라우팅 헤더**: `Mcp-Method`, `Mcp-Name` 추가 — 로드밸런서가 바디 파싱 없이 라우팅 가능.

## 카테고리 6: Context Engineering (prompt caching, context window 관리, memory/RAG)

### 논문 & 리포트

**arxiv:2603.09619 — "Context Engineering: From Prompts to Corporate Multi-Agent Architecture"** (2026-03)
- Context engineering(CE)을 독립 학문으로 정의. "prompt engineering이 '어떻게 물을까'를 다루면, context engineering은 '에이전트가 행동 순간에 무엇을 알고, 보고, 기억하는가'를 다룬다."
- 5가지 context 품질 기준 제안: relevance(관련성), sufficiency(충분성), isolation(격리), economy(경제성), provenance(출처 추적).
- Context를 에이전트의 operating system으로 프레임화.
- **Jayden 적용**: CLAUDE.md 작성 시 이 5기준으로 체크리스트화. "충분하지만 경제적인" context 설계로 token 비용 절감.
- URL: https://arxiv.org/abs/2603.09619

**arxiv:2601.06007 — "Don't Break the Cache: Prompt Caching for Long-Horizon Agentic Tasks"** (2026-01)
- OpenAI, Anthropic, Google 3개 제공사 prompt caching 비교 실험.
- 핵심 발견: 동적 tool 결과를 system prompt 끝에 배치하고, function calling 결과를 캐시 블록 밖으로 분리하면 "naive full-context caching보다 일관된 효과" 달성. 최대 90% 토큰 비용 절감 가능.
- **Jayden 적용**: Claude API 호출 시 정적 시스템 프롬프트(CLAUDE.md 내용)를 앞에, Supabase 쿼리 결과 등 동적 내용을 뒤에 배치하는 구조로 cache hit rate 최대화.
