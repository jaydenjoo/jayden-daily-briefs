## 1차 출처 — Anthropic Engineering Blog

### [Cat. 6 — Context Engineering] "Effective context engineering for AI agents"

- **URL**: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- **게시일**: 2025-09-29 (Prithvi Rajasekaran 외 Anthropic Applied AI팀)
- **90일 경과 여부**: 약 9개월 전 — 단, Anthropic 1차 출처로 포함

**핵심 주장**: context engineering은 "에이전트가 멀티턴으로 동작하는 긴 시간 동안 LLM의 제한된 attention budget 안에 어떤 정보를 넣을지 설계하는 것"이며, prompt engineering의 상위 개념이다.

**4가지 기법** (원문 기반):

| 기법 | 설명 |
|---|---|
| **Compaction** | context 한계 도달 시 대화 히스토리를 요약·압축 후 재시작 |
| **Structured Note-Taking** | 에이전트가 `NOTES.md` 같은 외부 메모를 유지하고 나중에 조회 |
| **Sub-Agent Architectures** | 전문 sub-agent가 집중 작업 후 압축 요약만 orchestrator에 반환 |
| **Just-in-Time Context Retrieval** | 가벼운 식별자만 유지하다 필요 시점에 tool로 데이터 동적 로드 |

**Jayden 스택 적용**: Claude API 호출 시 시스템 프롬프트 + RAG 청크 + 롤링 대화를 어떻게 배치할지 설계 기준이 됨. Anthropic은 하나의 요청에 최대 4개 cache breakpoint 허용 → 시스템 프롬프트, 도구 목록, RAG context를 각각 독립 캐시 가능. 실사용 시 API 비용 최대 90% 절감 보고됨.
